# Wyrmwatch 0.2.4

This candidate supersedes the unpublished 0.2.3 candidate. It includes the saved-server workspace, safer world import and restore recovery, smaller shared-runtime packages, operation guidance, and a correction that keeps disappearing previously loaded preferences from disabling the background manager. Publication still requires explicit approval of the new immutable `v0.2.4` tag at its exact verified source commit.

- Create a server or import one reviewed world `.sav` into a standard managed installation. Import preserves the source and rechecks its fingerprint; configuration, character files and passwords are not copied. Previously connected profiles remain compatible.
- Recover the observed fresh SteamCMD exit-7 metadata failure with one bounded retry. Resume a prepared installation only when this workspace's receipt and complete file inventory still match.
- Protect save locations across connected and disconnected profiles. Interrupted restores retain a durable journal, block Start/writes and require explicit verified reconciliation. Recover missing/empty Saved folders and distinguish configuration-only from full world restores.
- Preserve owned Windows launcher children and Linux launcher/session handoffs while keeping shutdown graceful. Unowned and inaccessible processes remain protected.
- Keep previously loaded settings fail closed if their file or directory disappears. Bounded read failures leave the background manager running instead of substituting first-run defaults. Genuinely new files still use defaults.
- Show truthful operation phases, elapsed time, persistent errors, prerequisite explanations and destination links. Improve structured setup reviews, retry state, centered inputs, dark/light layouts, keyboard labels and bundled-font portability.
- Share one bundled .NET runtime between desktop and manager, retain matching source/notices and omit debugging symbols. Remove remote control and automatic app-release checks; manual update checks remain available.
- Isolate native process fixture tests that share the host's global inventory. Add missing-settings and simultaneous exited/unreadable-process regressions plus actionable failure diagnostics. The fail-closed process guard and its timeouts are unchanged. The exact historical CI failure causes remain unconfirmed.
- Keep a durable publication hold for 0.2.3 in trusted release orchestration. Its existing tag, private draft and assets remain intact and cannot be automatically adopted as the corrected candidate.

Automatic maintenance and background operation remain off by default. Opening the app does not install or start a game server. Disconnect preserves existing installation/save/backup files. No existing profile or world is automatically migrated.

## Downloads after approval

- **Windows x64:** `Wyrmwatch-0.2.4-win-x64-setup.exe`, a per-user installer. It is currently unsigned.
- **Ubuntu/Debian x64:** `Wyrmwatch-0.2.4-linux-amd64.deb`.
- **Portable:** `Wyrmwatch-win-x64.zip` and `Wyrmwatch-linux-x64.tar.gz`.

Packages include the .NET runtime, matching source, AGPL license/notices and SHA-256 files. Successful current-master checks may prepare a private draft. Merging this code does not approve publication: a separately approved `v0.2.4` tag and successful matching package checks on both platforms are required. No existing tag is moved and no old draft assets are replaced.

## Verification and limits

Automated coverage uses disposable servers and structural world fixtures. Native Linux desktop flows and native Windows screenshot layouts were checked separately in the preceding UI work. These checks do not certify real Dragonwilds world/game compatibility, physical power-loss behavior, every DPI setting or native screen-reader behavior. Structural SAVE/SPUD validation does not prove a world will load in game. Linux remains a preview until verified with a real Linux game installation. Keep an independent world backup and follow the [installation guide](https://github.com/stephenjarrett/Wyrmwatch/blob/v0.2.4/docs/installing.md).
